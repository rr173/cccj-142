# csv-ingest — 多表 CSV 数据包校验入库工具

用 Python 标准库 + SQLite 实现的命令行工具。读取一个目录中的多表 CSV 数据包
及其 JSON 清单，核对表头、主键、必填值和跨表外键引用，输出：

- `valid/<表名>.csv`：每张表中仍有效的行（保留表顺序与表内记录顺序）；
- `quarantine.csv`：统一隔离文件，含原文件、逻辑记录序号、原始字段、全部原因；
- `report.json` / `summary.txt`：每张表的读取/有效/隔离数量，并按四类原因分别计数。

## 快速开始

```bash
# 运行单元测试（27 个用例，全部期望值手算写死）
python3 -I tests/test_ingest.py

# 一键复做验收：构建手算数据包 -> 入库 -> 独立断言，全过程写入 run.log
bash acceptance/run_acceptance.sh

# 直接调用
python3 -I bin/csv-ingest \
  --input-dir  <数据包目录> \
  --manifest   <数据包目录>/manifest.json \
  --output-dir <交付目录> \
  [--batch-size 1000] [--force] [--keep-db]
```

退出码：`0` 成功；`2` 清单不合法；`3` 数据包结构性失败；`1` 其他错误。

## 清单格式（只声明规则，绝不执行代码）

```json
{
  "version": "1",
  "tables": [
    {
      "name": "orders",
      "file": "csv/orders.csv",
      "columns": [
        {"name": "order_id"},
        {"name": "cust_id", "trim": true, "casefold": true},
        {"name": "amount"}
      ],
      "primary_key": ["order_id"],
      "required": ["amount"],
      "foreign_keys": [
        {"name": "fk_order_customer",
         "columns": ["cust_id"],
         "target_table": "customers",
         "references": ["cust_id"]}
      ]
    }
  ]
}
```

- 规范化只允许两个布尔开关：`trim`（去首尾空白）、`casefold`（大小写折叠，
  `str.casefold`）。任何未知键、非布尔值、类代码字符串都被拒绝；清单中没有
  任何可执行入口。
- 校验拒绝：重复表名、重复/缺失列定义、引用未定义列、无效外键（目标表/列不存在、
  两端字段数不一致、两端 trim/casefold 规则不一致、未引用目标完整主键）、
  越出输入目录的路径（绝对路径、`..`、盘符、反斜杠、NUL 均拒绝；符号链接逃逸
  在打开文件时用 `resolve()` 二次拦截）。

## 判定语义

1. **逻辑记录序号（lno）**：按 CSV 逻辑记录计数，**表头恒为逻辑记录 1**。
   引号字段中的嵌入换行只是同一条记录的一部分，不会被误报成多条。字节级状态机
   先预检整份文件，专门捕获 Python `csv` 模块会静默吞掉的“未闭合引号”。
2. **重复主键**：按该表声明的规范化规则比较，规范化后相等即重复；
   重复组内**每一行都隔离**，不存在“先到先留”。
3. **必填缺失**：原始文本为空字符串即缺失（主键列隐式必填；规范化只用于比较，
   不改变“是否为空”的判定，也不改写输出的原始文本）。
4. **外键**：必须匹配目标表中**唯一且最终有效**的规范化主键。
   - 外键列原始文本为空且该列未声明必填时，视为“未填写引用”，不产生外键原因；
   - 目标键完全不存在 → `MISSING_TARGET`；
   - 目标键存在但其全部承载行已隔离 → `REF_QUARANTINED`；
   - 该影响沿外键关系逐轮传播，直到某轮不再产生新隔离（不动点）。
5. **互相引用**：只要两端键唯一且均无其他错误，环上的记录在迭代开始前都是
   有效状态，因此合法互相引用整体保留。
6. **多原因并存**：一条记录的所有可确定原因都保留，按全局稳定序
   `DUP_KEY → MISSING_REQUIRED → MISSING_TARGET → REF_QUARANTINED` 排列，
   同码内按明细文本排序。

| 原因码 | 含义 |
|---|---|
| `DUP_KEY` | 规范化主键在表内重复 |
| `MISSING_REQUIRED` | 必填列（含主键）原始值为空 |
| `MISSING_TARGET` | 外键目标在目标表中不存在 |
| `REF_QUARANTINED` | 外键目标存在但已被隔离（含逐层传播） |

## 有界内存与“等待判断”的数据如何参与判定

进程内任何时刻只保留一批（`--batch-size`，默认 1000 行）数据，其余全部落在
SQLite 暂存库（`PRAGMA temp_store=FILE`、小页缓存），规模随磁盘而不是内存增长：

1. **结构解析阶段**：所有行（包括将来会被隔离的行）都流式写入暂存表，同时保存
   原始文本列与规范化副本列。此时它们都是“等待判断”的数据，但已经可被查询。
2. **重复识别**：对暂存表整表 `GROUP BY` 规范化主键（行值元组比较，无分隔符
   碰撞），因此先到/后到、文件遍历顺序都不影响谁被判定为重复。
3. **外键判定**：连接条件使用两侧的规范化副本列并走磁盘索引；目标表尚未被
   “宣判”的行同样参与匹配，所以互相引用不会被误杀。
4. **传播不动点**：每轮只新增 `REF_QUARANTINED`（`INSERT OR IGNORE` 幂等去重），
   轮数受“每轮至少新增一行”约束，天然有上界（不超过总行数）。
5. **交付**：有效表与隔离文件都用服务端游标 `fetchmany` 分批写出，不整表载入内存。

## 原子性与路径安全

- 所有处理先在输出目录旁的隐藏临时工作目录完成；成功后才把交付物移入正式目录，
  失败则清理临时目录与空占位目录，正式位置不会出现半成品。
- 任一文件编码错误、引号未闭合、表头不符、字段数错误，都会让**整包失败**
  （退出码 3），且不产生任何交付。
- 输出只包含清单声明的**相对文件名**与原始字段，不包含输入绝对路径，也不会读取
  输入目录之外的内容。
- 确定性：表按清单声明顺序处理、行按 `row_id`（即输入顺序）输出，原因按固定序
  排列；相同清单与文件内容在不同文件遍历顺序下产物逐字节一致（有测试覆盖）。
